# 2026-10-14 작업과 클라우드 반영 안내

오늘 작업 직전에 클라우드로 옮긴 서버에 아래 변경을 반영하기 위한 기록이다. 이 작업에서는 코드를 깃허브에 올리며, 클라우드 서버에 직접 반영하지 않는다.

## 오늘 바꾼 것

- 분리 채팅창에 현재 인원과 프로필 사진을 표시했다. 참여자 줄은 보기 선택 버튼 묶음과 같은 높이 44이며 좌우 끝도 맞췄다. 넘치는 사진은 +숫자를 눌러 넘긴다.
- 분리 창 바깥의 불필요한 세로 스크롤, 입력칸 아래와 오른쪽의 여백, 입력칸 바로 위 구분선을 정리했다. 작은 창에서는 미리보기를 줄여 입력칸을 확보한다.
- PC 방장에게 화면공유와 TTS 사이에 REC 버튼을 추가했다. 녹화 중에는 초록불과 진한 빨간 정지 네모가 보인다.
- 녹화 설정은 선택한 2번 시안을 따랐다. 화면 미리보기, 기본/선명 화질, 소리 함께 녹음, 저장 폴더 선택을 제공한다.
- 공유 영상과 공유자의 구석 얼굴을 합쳐 방장 컴퓨터의 선택한 폴더에 저장한다. 카메라 위치·모양·크기·반전·켜기/끄기를 따라간다. 채팅과 아래 참여자 얼굴 줄은 녹화에 포함하지 않는다.
- 마이크, 대화, 공유 소리, TTS를 함께 녹음할 수 있다. 다른 창에서 작업하는 동안에도 녹화한다. 공유 종료·교체, 퇴장, 방장 권한 해제 때 녹화를 끝내 저장한다.
- 녹화를 빼기로 했던 이전 결정은 사용자의 오늘 요청으로 바뀌었다. 새 설치 부품은 추가하지 않았다. 휴대폰 화면과 기존 음성 설정은 유지했다.
- 분리 창 제목줄의 최소화·최대화와 항상 앞에 뜨는 설정은 브라우저가 관리한다. 일반 창으로 바꾸는 기능은 이번에 추가하지 않았다.

## 클라우드 서버에서 반영하는 순서

1. 현재 서버의 코드 위치와 실행 방법을 확인한다. 저장되지 않은 변경이 있는지 `git status --short`로 확인하고, 클라우드 설정과 비밀 설정을 보관한다. 변경이 있으면 먼저 내용을 비교한다. 강제로 지우거나 덮어쓰지 않는다.
2. 저장소의 `main`에서 `git pull --ff-only origin main`으로 오늘 코드를 받는다. 실패하면 서버에 별도 변경이 있는지 확인한다. 깃 저장소 없이 파일로 옮기는 서버라면 위 변경 파일을 모두 반영한다. 특히 새 `public/record-worker.js`를 빠뜨리지 않는다.
3. 기존 설치 부품이 있는 서버라면 이번 변경 때문에 다시 설치할 필요는 없다. 프로젝트 폴더에서 `npm --prefix apps/web test`로 검사하고, `npm --prefix apps/web run build`로 웹 화면을 새로 만든다. 만들기에 실패하면 실행 중인 서비스를 새 코드로 바꾸지 말고 오류를 확인한다.
4. 클라우드에서 현재 쓰는 실행 방법으로 웹 서버를 다시 켠다. 클라우드의 운영체제와 실행 관리 방법은 아직 확인하지 않았으므로 집 PC용 명령을 그대로 쓰지 않는다. 웹 요청 처리 코드는 바뀌지 않았고, 통화 서버나 주소 연결 설정을 바꿀 필요도 없다.
5. 실제 방송 주소를 최신 PC 크롬·엣지로 열어 방장으로 입장한다. 화면공유와 구석 카메라를 켠 뒤 REC에서 폴더를 고르고 짧게 녹화한다. 끝낸 파일의 영상·얼굴 위치·소리를 확인한다. 일반 참여자에게 REC가 보이지 않는지, 분리 창의 참여자 줄과 입력칸도 확인한다. 확인 후에는 입장 화면으로 나온다.

## 유지해야 하는 서버 설정

- 클라우드의 `.env.local`, 통화 서버 설정과 비밀 키, 주소 연결 설정, 방 목록, 운영진 목록, 음성 모델과 실행 파일을 집 PC의 것으로 덮어쓰지 않는다. 이 파일들은 이번 커밋에 포함하지 않는다.
- `DOLIVE.lnk`는 컴퓨터마다 경로가 다른 바로가기라 이번 커밋에서 제외한다.
- 집 PC의 `scripts/start_dolive.ps1` 기본 실행은 DuckDNS 주소를 집 PC의 인터넷 주소로 갱신한다. 클라우드 이관 후 이 명령을 서버 반영용으로 실행하지 않는다. 옛 집 서버도 다시 켜지 않는다.
- 클라우드에 옛 `.next` 결과물만 복사하지 말고, 클라우드의 설정을 유지한 상태에서 새 코드를 빌드한다.
- 녹화는 서버 디스크가 아니라 녹화하는 방장의 컴퓨터에 저장한다. 폴더 선택은 안전한 연결 주소(HTTPS) 또는 localhost에서 지원된다.

## 확인 결과와 남은 확인

- 자동 시험 14개와 자료 형태 검사 통과. 오늘 변경한 녹화·참여자·공유·분리 창 파일의 코드 검사 통과. 실제 웹 만들기와 크롬 녹화 파일 생성·재생도 확인했다.
- 구석 위치·반전·카메라 켜기/끄기, 소리 포함/제외, 다른 창 작업 중 녹화, 공유 종료와 방장 권한 해제 때 저장을 확인했다. 실제 분리 창의 크기 변경·사진 넘기기·내부 채팅 스크롤도 확인했다.
- 자동 녹화 확인에서는 운영체제의 폴더 선택창 대신 브라우저의 확인용 폴더를 사용했다. 실제 폴더 선택창을 손으로 고르는 확인, 장시간 녹화, 클라우드에서의 전체 확인은 남아 있다.
- 방 화면 파일의 기존 전체화면 지원 확인에는 코드 검사 지적 1개가 남아 있다. 이번 변경과 관계없는 기존 문제이며 검사 규칙을 약하게 바꾸지 않았다.
