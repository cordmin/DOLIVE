# DOLIVE 가상 서버 전환 기록

## 확인한 상태와 합칠 내용

- 운영 주소는 `https://dolive.site/`이며 DigitalOcean DOLIVE 서버로 연결된다. 공개 웹은 정상 응답한다.
- GitHub `678b6a4`에는 Linux 설치·운영 코드와 오늘 만든 녹화·분리 채팅 참여자 표시가 이미 함께 들어 있다. 두 기능을 중복으로 합치지 않는다.
- 로컬에만 있던 `ac0ce78`의 1번 미리보기 그림을 최신 코드에 충돌 없이 적용했다. 기존 JPG를 없애고 `apps/web/app/opengraph-image.png`를 쓴다.
- 공개 사이트의 미리보기가 옛 주소를 가리키는 것을 확인했다. 이제 운영 설정 `DORMS_SITE_URL`을 사용하고, 없으면 `https://dolive.site`로 연결한다. 비회원 실제 서버 시험의 바깥 주소도 같은 방식으로 바꿨다.
- Linux 설치·통화·실행 관리 코드는 변경하지 않는다. 휴대폰 화면과 기존 음성 설정도 유지한다.
- `.agents/AGENTS.md`에는 일반 작업 규칙만 있고 `apps/web/CLAUDE.md`는 Next.js 지침을 가리켰다. 가상 서버 지침이 없어 공개 가능한 루트 `AGENTS.md`, `CLAUDE.md`를 추가한다. 개인 연결 정보가 있는 옛 지침은 개인 백업에 남긴다.

## 이 컴퓨터의 도구

- 프로젝트 루트 `.env.local`에 사용자가 지정한 `DIGITALOCEAN_API_KEY`를 저장했다. GitHub에서는 제외한다. 웹 앱의 `apps/web/.env.local`과 다른 파일이다.
- [공식 doctl](https://github.com/digitalocean/doctl) 1.186.0을 사용자 폴더 `.local/bin`에 설치하고 공식 파일 검사값을 대조했다. 새 PowerShell 창에서 `doctl version`으로 확인한다.
- doctl은 프로젝트 `.env.local`을 자동으로 읽지 않는다. 키를 명령 인자·출력에 넣지 말고 실행하는 동안만 `DIGITALOCEAN_ACCESS_TOKEN`으로 전달한다.
- 키로 서버 목록을 읽는 시험을 통과했다. 켜진 DOLIVE 서버가 새 주소의 연결 대상과 같았다. 다른 서버는 변경하지 않았다.
- [DigitalOcean Labs 작업 지침](https://github.com/digitalocean-labs/do-app-platform-skills)을 `digitalocean-app-platform`으로 설치했다. 다음 대화부터 도구 목록에 반영된다. 이것은 App Platform용이므로 현재 Droplet 관리에 적용하지 않는다. Droplet에는 프로젝트의 Linux 안내와 루트 지침을 쓴다.

## 서버에 반영하는 순서

1. 검사와 실제 변경 내용을 사용자에게 보여 주고 GitHub 반영을 확인받는다. 최신 main이 또 바뀌면 다시 비교한다.
2. SSH(열쇠로 접속하는 관리 통로)로 서버에 들어가 설치 위치, 실행 방식, 코드 수정 여부, 방송 중인지를 확인한다. 서버 비밀 설정·방·운영진·모델·인증서를 보존한다.
3. 기본 Linux 설치 방식이 맞고 점검 시간이 확보되면 `sudo dolivectl health`, `sudo dolivectl doctor`를 확인한 뒤 `sudo dolivectl update`를 실행한다. 백업·새 코드 받기·웹 만들기·다시 켜기를 처리하고 실패하면 이전 코드로 돌린다. [Linux 안내](linux/README.md) 13번을 따른다.
4. 새 주소에서 사진·녹화·분리 채팅을 확인한다. 카카오톡에 이미 보낸 링크에는 이전 결과가 남을 수 있어 새 메시지에서도 확인한다. 실제 폴더 선택과 장시간 녹화는 별도 확인한다.

## 관리자 접속

별도 관리자 웹 페이지는 없다. 기존 DOLIVE 화면을 아래 권한으로 사용한다.

1. **운영진**: `https://dolive.site/`에서 도름스 계정으로 로그인한다. 서버의 `server/config/staff.txt`에 등록된 운영진은 모든 방송을 관리한다. 기본 위치에서는 `sudo -u dolive nano /opt/dolive/server/config/staff.txt`로 등록한다. 목록 변경 뒤 방 권한은 다음 입장부터 적용된다.
2. **마스터**: 관리자 컴퓨터에서 아래 통로를 열고 창을 열어 둔 상태로 `http://localhost:13000`을 연다. 계정과 서버 주소는 실제 값으로 바꾼다. 추가 열쇠가 필요하면 `-i`로 파일을 지정한다.

   ```text
   ssh -N -L 127.0.0.1:13000:127.0.0.1:3000 -L 127.0.0.1:7880:127.0.0.1:7880 <계정>@<서버주소>
   ```

   집 서버를 켜는 것이 아니라 DigitalOcean 서버에 통로로 들어간다. 공개 주소에서는 마스터가 되지 않는다. 끝나면 방에서 나온 뒤 `Ctrl+C`로 통로를 닫는다.

서버 자체의 상태·요금·방화벽은 [DigitalOcean 제어판](https://cloud.digitalocean.com/)에서 본다. API 키는 SSH 열쇠를 대신하지 않는다.

## DuckDNS와 집 공유기 원상복구

1. 새 주소의 로그인·통화·화면공유를 확인한다. 도름스 등록 주소와 서버의 `DORMS_SITE_URL`, `LIVEKIT_PUBLIC_URL`, `DOLIVE_DOMAIN`도 새 주소와 맞는지 확인한다.
2. 옛 집 서버와 주소 갱신 작업이 꺼져 있는지 확인한다. Windows 서버 켜기 명령은 쓰지 않는다. 예약된 주소 갱신이 있으면 대상만 확인해 해제한다.
3. 공유기에서 DOLIVE 때문에 추가한 TCP 443, TCP 7881, UDP 50000~60000 연결 규칙만 확인해 삭제한다. 다른 규칙과 인터넷·TV 설정은 유지한다. 전체 초기화나 모두 삭제를 하지 않는다.
4. DOLIVE 때문에 추가한 서버 PC의 고정 주소 할당은 다른 서비스 사용 여부를 확인하고 해제한다. 컴퓨터 안의 수동 주소 설정도 확인한다. 자동 주소 받기로 바꾸면 잠깐 연결이 끊길 수 있어 현재 설정을 따로 남긴 뒤 변경한다.
5. [DuckDNS](https://www.duckdns.org/)에서 옛 DOLIVE 주소 항목만 삭제한다. 다른 주소와 클라우드 설정은 유지한다. 새 주소 확인 후 사용자와 합의해 진행한다.
6. Windows 방화벽의 DOLIVE 전용 허용 규칙도 확인해 필요 없으면 제거한다. Wi-Fi나 통신사 기본 설정은 추측으로 바꾸지 않는다.

과거 Windows 문서와 이관 백업 코드에 DuckDNS 언급이 남아 있어도 현재 운영에서는 쓰지 않는다. 과거 백업 복원을 위한 파일까지 무작정 삭제하지 않는다.

## 실제 서버 반영과 앞으로 작업하는 방법

2026-10-14에 서버로 직접 접속해 최신 코드 `3250c8e`를 반영했다. 처음에는 `/opt/dolive`에 깃 기록이 없었으므로 새 폴더에 GitHub 코드를 받아 검사하고 기존 폴더와 교체했다. 현재 서버는 Git으로 관리되며 이후에는 기존 `dolivectl update`를 사용할 수 있다.

- SSH 접속 열쇠를 등록했고 화면에 표시된 서버 확인값과 접속 대상의 확인값을 대조했다. 이 관리자 컴퓨터에서 `ssh dolive`로 접속되는 것을 확인했다. 주소와 열쇠 위치는 사용자 폴더의 `.ssh/config`에 있으며 저장소에 올리지 않는다.
- 반영 전 모델 포함 백업과 이전 전체 폴더를 서버에 보관했다. 반영 후 설정·목록·인증서 백업은 관리자 컴퓨터의 프로젝트 밖 개인 백업 폴더에도 받았다. 비밀값이 들어 있으므로 공개하지 않는다.
- 자동 시험 14개, 실제 서버의 웹 만들기, 네 목소리, 채팅·사진·빈 방 정리, 공개 주소의 통화 연결 시험을 통과했다.
- 전환 중 새 폴더의 Caddy 접근 권한을 바로잡았다. 확인용 시험이 목록의 줄바꿈을 바꿔 보존 검사에서 한 번 이전 상태로 돌아갔으나, 내용이 같은 것을 확인한 뒤 원래 파일을 그대로 보존해 최종 반영했다.
- 공개 사이트가 새 사진 주소를 내보내며, 선택한 1번 그림과 공개 사진의 파일 검사값도 같았다. 최종 웹·통화·HTTPS 서비스가 모두 켜져 있음을 확인했다.
- 실제 관리자 등록은 인증된 도름스 닉네임 기준으로 서버의 운영진 파일에 반영했다. 입장 화면에서 자유롭게 입력한 이름으로 권한을 주지 않는다. 실제 운영진 목록은 비공개로 유지한다.

앞으로는 사용자가 명령을 복사하거나 관리 화면을 클릭하는 대신 작업자가 아래 순서로 직접 진행한다.

1. 로컬과 GitHub의 최신 코드를 비교하고 필요한 변경을 검사한다. 커밋·올리기는 사용자가 요청한 범위에서 진행한다.
2. `ssh dolive`로 접속해 서버 코드의 변경 여부와 실제 참여 인원, `sudo dolivectl health`를 확인한다. 방송 중이면 반영 시간을 조율한다.
3. 최신 GitHub 코드를 반영할 때 `sudo dolivectl update`를 사용한다. 비밀 설정·방송·운영진·모델·인증서를 보존하며, 실패하면 이전 상태로 돌리고 원인을 확인한다.
4. `sudo dolivectl health`, `sudo dolivectl doctor`와 실제 공개 페이지를 확인한다. 변경에 따라 통화·글 읽기 시험을 추가하며, 이미 통과한 검사를 이유 없이 반복하지 않는다.
5. 적용한 코드 번호, 확인 결과, 백업, 남은 일을 기록하고 사용자에게 완료 결과를 알린다. 공개 문서에 접속 비밀값이나 운영진 목록을 적지 않는다.

이 컴퓨터에서 마스터로 접속할 때는 아래 통로를 열어 두고 `http://localhost:13000`을 연다. 운영진은 통로 없이 `https://dolive.site/`에 등록된 도름스 계정으로 로그인한다.

```text
ssh -N -L 127.0.0.1:13000:127.0.0.1:3000 -L 127.0.0.1:7880:127.0.0.1:7880 dolive
```

## 남아 있는 확인

합친 코드의 자동 시험 14개와 웹 만들기를 통과했다. 생성된 페이지의 미리보기 주소가 `https://dolive.site/opengraph-image.png`인 것도 확인했다. Linux 실행 파일과 녹화·참여자 기능은 최신 GitHub 코드와 동일하다. 검사 폴더에는 기존 설치 부품과 모델을 따로 준비했으며 서버를 켜거나 옛 주소를 갱신하지 않았다.

서버 내부 접속과 실제 코드 반영은 완료했다. 실제 PC에서 녹화 파일 저장과 모바일 입장 동작을 다시 확인하는 일은 별도로 남아 있다. 설치 부품 검사에서 기존 높은 등급 보안 지적 8건이 나왔고 이번에는 프로그램 판을 바꾸지 않았으므로 별도 점검이 필요하다. 공유기와 DuckDNS 정리는 사용자가 정한 대로 마지막에 진행한다.
