# 도름네이션 확인 기록

감정 스티커 맨 위에 도름네이션을 추가했다. 현재 화면을 공유하는 사람을 먼저 고르고, 없으면 방송에 있는 방 주인·방장을 고른다. 받는 사람 이름을 제목에 넣고 1·2·3도름을 확인한 뒤 보낸다. 자신이나 비회원에게 보내지 못한다. 받는 도름스 회원 번호와 방장·화면공유 여부는 통화 서버에서 다시 확인한다.

로그인과 보내기 허용은 도름스 공식 도구 0.5.0의 `--donations-at-login` 방식을 사용한다. 로그인할 때 도름네이션 동의도 함께 요청하고 로그인 콜백에서 전송 권한을 준비한다. 회원은 로그인만 선택할 수도 있다. 바깥 주소를 바로잡던 기존 로그인 코드를 남겼고, 로그아웃에는 보내기 권한 폐기를 합쳤다. 비밀 권한은 JavaScript가 읽지 못하는 쿠키에만 둔다. 출처가 같은 보내기 요청만 받는다.

방 안에서 도름네이션을 열거나 보낼 때 권한이 없어도 현재 페이지를 다른 곳으로 넘기지 않는다. 안내를 표시하고, 회원이 직접 누를 때만 새 창에서 로그인·허용을 진행한다. 새 창은 `/dorms-donation-allowed`에서 끝나 방송방을 중복으로 열지 않는다. 원래 창에서 권한을 다시 확인한 뒤 보낸다. 홈 화면에 추가한 웹앱과 바깥 브라우저가 쿠키를 공유하지 않는 환경은 새 창의 허용이 원래 창에 반영되지 않을 수 있으므로 방송을 마친 뒤 원래 앱에서 다시 로그인한다.

응답을 못 받아도 같은 요청 번호·상대·금액으로 다시 확인한다. 브라우저가 보내기 내용을 기억하므로 새로고침 뒤에도 새 요청을 만들지 않는다. 성공이 확인된 뒤에만 완료를 표시한다. 잔액과 남은 한도는 서버 응답으로 확인하되 화면에는 숫자를 표시하지 않는다. 서버가 방에 보낸 성공 알림으로 1도름당 도름이 한 마리가 내려온다. 같은 성공 알림은 두 번 그리지 않는다. 한도와 잔액은 도름스 응답을 사용한다.

도름이 원본은 제공된 프로젝트의 `web/public/doreumi/fallback.webp`다. 도름이 © 아인T, CC BY-NC 4.0. 원본을 참고한 그림 중 사용자가 고른 입체 고급형·투명 우산·애니메이션·가을 나뭇잎만 사용한다. 우산을 손에 쥔 네 그림의 배경을 투명하게 만들고 `public/doreumi/donation`에 담았다. 무작위 보내기 번호로 모습을 고르므로 같은 보내기는 모든 사람에게 같은 모습이다. 우산과 도름이는 함께 좌우로 이동하며 내려온다. 몸통 중심을 기준으로 좌우 4도씩 살짝 기울고, 흔들리는 속도도 조금씩 다르다.

## 확인한 것

- 2026-10-28: 운영 사이트 등록 조회에서 `approved`, 로그인 동시 허용 지원을 확인했다. 로그인 시작·콜백의 별도 PKCE, 로그인과 전송 권한 연결, 로그인만 선택, 권한 교환 장애 시 로그인 유지, 미승인·이전 서버에서 일반 로그인 유지, 방 안에서 페이지 이동 금지와 새 창 완료 경로를 격리 시험에 추가했다. 이전의 자동 왕복 코드는 제거했다. 아래 2026-10-12 기록은 당시 동작의 이력이다.
- 2026-10-12: 브라우저의 도름네이션 허용증이 없다는 이유로 도름스에서 처음 허용하는 회원이라고 잘못 판단하던 처리를 고쳤다. 로컬 허용증 없음은 `connection_required`, 만료·로그인 변경은 `permission_expired`로 구분한다. 도름네이션 창은 이 경우 공식 허용 주소로 한 번 이동해 기존 허용 여부를 도름스가 판단하게 하고, 방에 돌아오면 창을 이어서 연다. 허용증을 새로 받기만 하며 자동으로 도름을 보내지 않는다. 10분 안에 같은 방에서 반복 왕복하지 않고, 쿠키 저장 실패는 [연결 다시 확인] 안내를 띄운다. 실제 철회·사용 중지·연결 장애에는 자동 재허용하지 않는다. 과거 사용자의 허용증이 언제·왜 사라졌는지는 당시 브라우저 기록이 없어 확정하지 못했다.
- `node tests/donation-connection.cjs`: 허용증 유실·만료·최초 동의·로그인 만료에도 실제 도름네이션 창이 방송 페이지를 유지하고 새 창으로만 허용을 안내하는지 확인한다. 미승인·철회·장애는 안내로 처리한다. `donation.cjs`에는 로그인 시 전송 권한 교환, 기존 허용자의 쿠키 유실 후 새 허용증 받기와 연결 확인 때 전송하지 않는 시험이 있다. 실제 회원의 도름스 왕복은 별도 확인이 필요하다.
- 2026-10-11: 도름스 허용으로 화면을 떠날 때 통화 연결이 끊기면서 첫 화면 이동과 입장 표시 삭제가 함께 실행되던 문제를 고쳤다. 화면 이동으로 생긴 연결 끊김은 퇴장 처리에서 제외한다. 실제 나가기·강퇴·방송 종료는 유지한다. `node tests/donation-return.cjs`로 이동 중 표시 유지와 복귀 뒤 퇴장을, `node tests/donation.cjs`로 허용 후 방 주소와 허용 기록 저장을 확인한다. 실제 회원의 허용 완료는 별도 확인이 필요하다.
- `node tests/donation.cjs`: 격리된 가짜 도름스에서 실제 로그인 코드의 서명 확인, 최초 보내기 허용, 1·3도름, 같은 요청 재시도, 보내진 뒤 응답 끊김, 회원·화면공유 확인, 자기 자신 거절, 잘못된 출처 거절, 승인 전·검토 중·중단 거절, 연결 허용 철회, 권한 만료, 잔액 부족, 하루 한도 소진, 로그아웃을 확인한다. 실제 도름스나 운영 회원의 도름은 사용하지 않는다.
- `node tests/donation-reactions.cjs`: 1·2·3도름의 마릿수, 선택한 네 그림만 사용, 중복 알림 무시를 확인한다.
- `node tests/room-rules.cjs`: 기존 방 권한과 비회원 입장 규칙을 확인한다.
- 글자·자료 형태 검사와 운영용 만들기를 실행한다.
- 예전 `/donation-preview` 확인 화면과 시안 자료는 정리 후 사용자 요청으로 삭제했다. 현재 실행 코드와 사용 중인 그림, 사용 조건 기록은 유지한다.

## 실제 사용 전 남은 확인

2026-10-28 운영 주소 `https://dolive.site`의 등록 상태는 `approved`, `donations.atLogin`은 `true`로 확인했다. 승인 신청이나 회원 허용을 대신 처리하지 않았다. 승인 상태와 회원 동의는 다른 것으로, 각 회원이 로그인하면서 도름네이션을 허용해야 한다.

실제 도름스의 로그인·최초 허용·보내기·철회·로그아웃은 별도 시험 회원과 시험 잔액이 준비된 뒤 확인해야 한다. 현재 가짜 시험 결과만으로 실제 전송까지 확인했다고 말하지 않는다.

서버를 다시 켜면 메모리의 상대 확인 기록이 사라진다. 결과가 미확정이고 상대도 방에서 나갔다면 같은 요청을 거절하고 계속 확인 대기로 남긴다. 이 경우 새 번호로 재전송하지 말고 도름스에서 원래 보내기 결과를 확인해야 한다.
