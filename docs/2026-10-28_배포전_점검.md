## 찾아서 고친 문제

영상 요소가 전체화면인 상태에서 상위 문서에 바로 전체화면을 요청하면, 이전 영상에도 전체화면 상태가 남았다. 채팅이 논리적으로 열려 있어도 영상이 화면 전체를 덮는 현상을 실제 브라우저에서 확인했다.

`landscape-chat.ts`에서 영상 전체화면을 먼저 종료한 뒤 방 전체화면을 요청하도록 수정했다. 수정 전에는 `:fullscreen` 요소가 HTML과 영상 두 개였고, 수정 후에는 HTML 하나만 남으며 영상·채팅의 경계가 나뉘는 것을 확인했다. 자동 검사에도 종료 → 방 전체화면 순서를 추가했다.

## 배포 전에 남은 절차

- 점검 기준 GitHub `main`은 `2ac7b13`이었다. 위 전체화면 최종 수정과 옛 로컬 실행 자료 정리를 이번 커밋에 포함한다. 배포 전에는 GitHub의 최종 커밋과 운영 서버의 코드를 따로 확인한다.
- 현재 서버는 이전 코드 `46ccd5d`이며 배포·재시작·selftest·실제 회원의 도름 전송은 하지 않았다.
- 실제 Android·iPhone의 터치감·회전·전체화면과 실제 도름스 시험 계정의 최초 동의·전송은 추가 확인이 필요하다. 브라우저 크기 시험과 가짜 도름스 검사를 실제 기기·실제 회원 시험으로 보고하지 않는다.
- Windows에서 Linux 설치·재부팅 전체 시험은 하지 않았다. 이번 서버 점검은 운영 상태를 읽은 결과다.
- 배포는 참여 상태를 다시 확인하고 최신 백업을 만든 뒤 기존 `sudo dolivectl update` 절차로 진행한다. 서버 비밀 설정·목록·모델·인증서를 로컬 설정으로 덮어쓰지 않는다.

## 같은 날 실제 배포 결과

사용자의 배포 요청 후 접속자 0명과 서버의 코드 수정 없음, 충분한 여유 공간을 확인하고 `sudo dolivectl update`로 `46ccd5d`에서 `0e87378`로 반영했다. 위의 배포 전 절차·미반영 설명은 점검 당시 상태이며, 실제 운영 서버도 이제 `0e87378`이다.

- 자동 백업: `/var/backups/dolive/dolive-backup-20261028-014835-792.tar.gz`. 압축 검사 통과.
- 운영 서버에서 웹 빌드 완료, 웹·LiveKit·Caddy 정상. health와 doctor 통과.
- 업데이트 중 Caddy의 공개 설정 파일이 0600으로 생성돼 별도 서비스 계정이 읽지 못했다. `/opt/dolive/server/linux/Caddyfile`만 0644로 바로잡고 Caddy를 다시 켜 정상 복구했다. 비밀 환경 파일의 권한은 바꾸지 않았다. 설치 도구의 권한 처리 자체는 이번에 수정하지 않았으므로 다음 업데이트에서도 이 공개 파일의 읽기 권한을 확인해야 한다.
- 운영 환경 파일·운영진 목록·방송 목록은 배포 전후 SHA-256이 모두 일치했다. 모델 9개와 HTTPS 인증서도 doctor에서 정상 확인했다.
- 공개 사이트 HTTP 200, 공개 CSS에 새 모바일 배치 포함, 공개 미리보기 그림과 소스 그림의 검사값 일치.
- 실제 공개 주소 `wss://dolive.site`의 WebSocket 연결 및 SDK 입장·퇴장 검사 통과. 확인용 방은 삭제했고 종료 시 방 0개·참가자 0명이었다.
- 네 목소리 F2·F1·M1·demon에서 실제 WAV 합성 확인.
- 실제 공개 로그인 시작 응답이 도름스의 `donation` 권한과 로그인용과 다른 전송용 PKCE를 요청하며, 돌아올 주소가 `https://dolive.site/api/auth/dorms/callback`임을 확인했다. 회원 동의와 실제 도름 전송은 대신 수행하지 않았다.
- 방송 목록의 줄바꿈까지 다시 쓰는 전체 selftest는 실행하지 않고, 목록을 수정하지 않는 통화 연결·음성 검사만 따로 실행했다. 실제 휴대폰과 시험 회원을 통한 확인은 여전히 별도다.

## 배포 후 휴대폰 제보에 대한 추가 수정 (로컬 검증)

- 전체화면은 사용자가 영상의 전체화면 버튼 또는 위 쓸기를 선택할 때만 요청한다. 입장·채팅 열기·사진 선택 후 첫 터치로 자동 진입하지 않는다.
- 지원되는 휴대폰에서는 선택 시 방 문서를 전체화면으로 두고 영상만 보이게 시작한다. 채팅 아이콘은 채팅 표시만 바꾸므로 전체화면 종료나 방향 잠금 해제를 요청하지 않는다.
- 문서 전체화면 미지원이면 기존 기본 영상 전체화면 경로를 사용한다. 실제 iPhone에서의 실행 확인은 아직 하지 않았다.
- 가로 전체화면에서 아래 쓸기는 현재 전체화면을 종료한다. 채팅 아이콘은 영상 칸 대신 화면 상단·오른쪽의 안전 여백을 기준으로 고정했다.
- 자동 검사 17개와 웹 빌드 통과. 이 추가 수정은 아직 커밋·푸시·운영 반영하지 않았다.
