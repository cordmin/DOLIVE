# 프로젝트 정리 기록

2026-10-11. 작업자 4명이 파일 조사, 서버 코드 정리, 화면 코드 정리, 독립 교차검증을 나눠 진행했다. 현재 사용자 규칙은 맨 위 `AGENTS.md`를 따른다.

## 추가 삭제

같은 날 사용자가 불필요 자료 삭제를 요청하여 아래 자료를 프로젝트에서 없앴다. 영구 삭제 명령은 자동 안전 검사에서 거절되어, 되살릴 수 있는 윈도우 휴지통으로 보냈다. 휴지통을 비우지는 않았다.

- `docs/archive` 전체: 옛 기획서·시안 화면·그림 원본·사용하지 않는 사진·확인용 소리·별도 도름이 참고 프로젝트 등 1,693개 파일, 약 110.6MB.
- `docs/donation`의 옛 화면 그림 18개와 그림 생성 기록 1개. 실제 사용 설명과 확인 기록인 `README.md`는 유지했다.
- `server/logs/types-before-cleanup`: 이미 새로 만든 옛 자동 생성 검사 기록.

삭제 뒤 자동 시험 9개를 다시 통과했고, 서버를 껐다 켜 새로 만들기와 통화·웹 화면·바깥 연결 정상 상태를 확인했다. 실행 코드에서 삭제한 자료를 가리키는 경로도 남아 있지 않다.

현재 쓰는 프로필 사진·후원 그림·목소리 모델·자산 사용 조건·서버 설정·실행 프로그램은 그대로다. 아래 표는 삭제 전에 수행한 조사와 임시 보관 과정의 기록이며, 표의 보관 폴더는 이제 존재하지 않는다.

- 서버 켜기 창의 상태 구분과 고른 프로그램만 다시 켜기 시험 통과.

- 새 코드의 운영용 만들기 성공. 통화 서버·웹 화면·바깥 연결 모두 정상 응답.
- 마지막 다시 켜기 뒤 입장 화면, 실제 프로필 사진, 후원 그림 네 개의 응답과 옛 시안 주소가 없어진 것도 확인했다.

- 실제 서버의 `room-lifecycle.cjs` 통과: 한 명이 남으면 기록 유지, 마지막 퇴장 때 글·사진 삭제, 읽어 주는 음성 종료, 옛 입장권 차단.

- 다른 작업자가 이동한 함수 내용과 서버 변경을 원문과 비교했다. 화면의 글자와 꾸밈도 동일함을 확인했다.
- 실제 입장 화면의 그림·목록을 브라우저에서 확인했다. 앱 안의 확인용 브라우저는 통화 연결 설정을 지원하지 않아 방 연결 후 조작 확인은 끝내지 못했다. 연결 확인은 실제 서버 시험의 통화 참여자로 수행했다. 확인 탭은 `/`로 돌려놓았다.

## 남은 확인과 기존 검사 지적

`npm run lint`에는 원래부터 오류 4개와 경고 5개가 있었다. 다른 작업자가 정리 전 원문에도 같은 지적이 있음을 확인했다. 입장 화면의 이동 처리, 후원 창 초기값, 분리 창 지원 확인, 저장된 음성 설정을 읽는 시점과 관련된다. 이번에는 검사 설정을 약하게 바꾸거나 동작 시점을 바꾸지 않았다.

크롬·엣지 실제 통화 화면에서 카메라, 공유 시작·종료, 채팅 분리 창을 손으로 눌러 보는 확인은 남아 있다. 휴대폰 화면의 꾸밈과 동작 코드는 바꾸지 않았다. 실제 도름스 로그인·후원 연결 철회 확인은 기존 인수인계 문서의 남은 사항과 같다.

## 앞으로 확인하는 순서

1. 프로젝트 폴더에서 `npm --prefix apps/web test`를 실행한다.
2. 서버가 켜진 상태에서 `apps/web` 폴더로 들어가 `node tests/room-rules.cjs --live`, `node tests/room-lifecycle.cjs`를 순서대로 실행한다. 확인용 방만 쓰고 끝나면 치우는 시험이다.
3. 코드를 바꾸면 서버를 껐다 켜서 실제 화면을 확인한다. 방 확인을 마친 브라우저는 반드시 `/`로 나온다.

커밋과 원격 저장소 올리기는 하지 않았다.

## 2026-10-12 휴대폰·블루투스 마이크 연결 개선

- 마이크를 잡기 전에 지원되는 휴대폰 브라우저에 통화용 소리 설정을 요청한다. 켜짐이 바뀔 때 이전 소리 설정으로 잠깐 되돌아가던 정리 동작은 퇴장 때만 하도록 나눴다.
- 권한을 받은 뒤 브라우저가 알려 주는 실제 마이크 목록을 확인한다. 기본 장치 별명은 중복으로 세지 않는다. 마이크가 하나면 바로 켜고, 여러 개면 선택 후 소리를 보낸다. 선택 전 미리 잡은 마이크는 다른 사람에게 보내지 않고, 취소 때 바로 멈춘다.
- 고른 마이크는 정확한 장치 번호로 요청한다. 브라우저가 다른 장치 번호를 돌려주면 켜지 않는다. 이전에 고른 마이크가 없어지면 다른 마이크로 조용히 바꾸지 않고 다시 고르게 한다. 선택 기억은 방 안에서만 유지한다.
- 오른쪽 클릭·꾹 누르기로 [마이크 설정]을 열고 [다시 연결]한다. 차량 마이크가 목록에 없을 때는 휴대폰의 소리 연결에서 바꿔야 한다고 안내한다.
- 장치 변경 알림에는 0.4초 기다렸다가 켜진 마이크만 한 번 새로 잡는다. 3초 안에 반복하지 않는다. 끊긴 마이크는 통화 도구에 이미 있는 복구를 그대로 쓰고, 복구 후 고른 장치인지 확인한다. 조용히 있는 사람에게 소리가 없다는 이유로 재연결하지 않는다.
- 늦은 권한 허용, 창 취소, 사용자 끄기, 방장 끄기, 복구 중 끄기, 퇴장 때는 새 마이크를 켜지 않도록 막는다.
- 자동 시험 11개와 글자·자료 형태 검사 통과. 새 파일과 수정한 소리 파일의 코드 검사 통과. 실제 아이폰·차량 블루투스 장비가 없어 물리적인 마이크 경로 확인은 남아 있다. 브라우저가 장치 번호를 제공하지 않거나 휴대폰 내부에서 경로를 바꾸는 경우까지 고쳤다고 보장하지 않는다.
- 참여자가 0명임을 확인한 뒤 서버를 다시 켰고 통화 서버·웹 화면·바깥 연결이 정상 응답했다. 실제 방 화면의 마이크 버튼과 권한 거부 안내를 확인했다. 확인용 브라우저가 마이크 접근을 거부해서 실제 소리 전송 시험은 하지 못했다. 확인용 탭은 입장 화면으로 나왔다.

## 2026-10-14 분리 채팅 참여자 줄과 여백 정리

- 보기 선택 버튼 바로 아래에 1번 시안의 얇은 참여자 줄을 추가했다. 버튼 묶음과 참여자 줄의 좌우 끝을 같은 위치에 맞췄다.
- 참여 인원과 24 크기의 프로필 사진을 한 줄로 표시한다. 음성 참여자는 기존 사람 목록처럼 제외한다. 사진에 마우스를 올리면 이름이 보이고, 넘치는 사람은 +숫자를 눌러 다음 묶음을 본다. 창을 줄이거나 늘리면 사진 수가 맞춰진다.
- 작은 창의 기본 바깥 여백을 없애고 높이를 작은 창 자체에 맞췄다. 창 전체에는 스크롤이 생기지 않고 글이 많을 때 채팅 내용만 움직인다. 입력칸 위 구분선은 없애고 좌우 여백 10, 아래 여백 8로 줄였다. 일반 방과 휴대폰 입력칸은 그대로다.
- 형식 검사와 웹 만들기, 얼굴 목록 넘기기 시험 통과. 수정한 참여자·공유 화면·분리 창 파일의 코드 검사도 통과했다. 방 화면 파일에는 기존 전체화면 지원 확인의 검사 지적 1개가 남아 있으며 이번 변경과 관계없다.
- 실제 서버를 껐다 켜고 통화 서버·웹 화면·바깥 연결이 모두 정상임을 확인했다. 실제 크롬의 작은 창에 사람 12명과 음성 참여자 1명을 연결해 인원 제외, 사진 넘기기, 이름 표시 구조, 320~680 폭의 창 크기, 많은 글의 내부 스크롤, 공유 화면·내 얼굴·채팅만 전환을 확인했다. 확인 탭은 입장 화면으로 나왔고 확인용 방과 참여자는 정리했다.

## 2026-10-14 방장 녹화와 참여자 줄 높이

- 참여자 줄을 위의 보기 선택 묶음과 같은 44 높이로 맞췄다. 아주 작은 분리 창에서는 미리보기를 줄여 입력칸이 가려지지 않게 했다.
- PC 방장에게 화면공유와 TTS 사이의 REC 버튼을 추가했다. 녹화 중에는 초록불과 진한 빨간 정지 네모를 표시한다. 휴대폰에는 추가하지 않는다.
- 사용자가 고른 2번 설정창처럼 왼쪽 미리보기, 오른쪽 기본/선명·소리 함께 녹음·저장 폴더 선택을 넣었다. 공유 화면과 얼굴이 함께 담긴다는 설명 문구는 넣지 않았다.
- 브라우저 기본 기능만 쓴다. 공유 영상과 공유자의 구석 얼굴을 별도 작업 공간에서 합쳐 다른 창에서 작업하는 동안에도 계속 녹화한다. 얼굴 위치·모양·반전·크기와 카메라 켜기/끄기를 따라간다. 공유 화면 아래 참여자 얼굴 줄과 채팅은 녹화 대상에 넣지 않는다.
- 영상은 서버로 올리지 않고 선택한 폴더에 1초씩 쓴다. 현재 크롬에서 일반적인 MP4 영상과 소리 형식(H.264/AAC)을 확인했고, 지원하지 않는 브라우저는 가능한 MP4/WebM 형식을 고른다. 녹화가 끝나야 파일 저장이 마무리된다. 녹화 중 새로고침·브라우저 종료에는 브라우저 확인창을 띄우고, 공유 종료·교체·퇴장·방장 권한 해제에는 녹화를 끝내 저장한다.
- 자동 시험 14개, 형식 검사, 수정한 녹화·참여자·공유·작은 창 파일의 코드 검사와 실제 웹 만들기 통과. 실제 크롬에서 녹화 파일을 만들어 영상과 소리를 확인했다. 구석 위치, 좌우 반전, 카메라 껐다 켜기, 소리 선택, 다른 창 작업 중 녹화, 공유 종료 저장, 방장 권한 해제 후 버튼 제외와 저장을 확인했다. 파일 분석으로 소리 포함 파일의 H.264/AAC와 소리 제외 파일의 영상만 있는 것도 확인했다.
- 자동 시험은 운영체제의 폴더 선택창 대신 브라우저의 확인용 폴더를 반환해 같은 파일 쓰기 기능을 시험했다. 실제 폴더 선택창을 손으로 고르는 확인과 장시간 녹화 시험은 남아 있다.
- 작은 창 제목줄의 최소화·최대화 버튼과 항상 앞에 뜨는 설정은 사이트가 바꿀 수 없어서 기존 방식을 유지했다. 일반 창으로 여는 기능은 추가하지 않았다. 확인 탭은 입장 화면으로 나왔고 임시 방·참여자는 정리했다.
