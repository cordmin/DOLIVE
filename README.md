# DOLIVE

**살짝 도라있는 교육 방송**

[DOLIVE 입장하기](https://dolive.site/)

DOLIVE는 동호회에서 음성으로 대화하고, 화면과 카메라를 공유하며 채팅하는 웹사이트입니다. 참여자는 별도 프로그램 없이 브라우저로 들어옵니다.

현재 서비스는 **DigitalOcean 가상 서버에서 운영**합니다. 집 컴퓨터의 서버와 기존 DuckDNS 주소는 사용하지 않습니다. 이 저장소의 코드를 바꿔 GitHub에 올리는 것과 실제 운영 서버에 반영하는 것은 별도 작업입니다.

## 주요 기능

| 기능 | 내용 |
| :--- | :--- |
| 음성 대화 | PC·휴대폰 마이크로 대화하고 소리 크기 조절 |
| 화면공유 | 방장은 바로 공유, 일반 참여자는 방장의 허락 후 공유 |
| 카메라 | 누구나 켜기 가능. 공유 중 구석 얼굴, 공유가 없을 때 얼굴 모아 보기 |
| 채팅 | 글·사진·링크·반응, 나중에 들어온 참여자도 남아 있는 기록 보기 |
| 글 읽기 | TTS(글을 목소리로 읽기), 서연·하은·민준·마왕 목소리 선택 |
| 분리 채팅 | PC 방장이 화면공유 중 작은 창으로 채팅 분리, 참여 인원·프로필 표시 |
| 녹화 | PC 방장이 공유 화면과 공유자의 구석 얼굴을 합쳐 자신의 컴퓨터에 저장 |
| 방송 관리 | 방송 만들기·비밀번호·입장 조건·강퇴·마이크와 카메라 끄기·방장 넘기기 |
| 도름네이션 | 도름스 연결과 승인에 따른 후원 기능 |

휴대폰도 브라우저로 참여할 수 있습니다. 분리 채팅·녹화·카메라 배경 흐리기는 PC용 기능입니다.

## 입장과 권한

1. [dolive.site](https://dolive.site/)를 엽니다.
2. 도름스 계정으로 로그인하고 프로필 사진과 이름을 고릅니다. 비회원 입장이 허용된 방송은 로그인 없이 들어갈 수 있습니다.
3. 방송 목록에서 방송을 고르고 **LIVE 입장**을 누릅니다. 비밀번호가 있는 방송은 비밀번호를 입력합니다.

| 권한 | 할 수 있는 일 |
| :--- | :--- |
| 일반 참여자 | 대화·채팅·카메라, 허락받은 화면공유 |
| 방 주인 | 자신이 만든 방송 관리, 도름스 회원에게 방장 넘기기 |
| 운영진 | 모든 방송 관리. 서버의 운영진 목록에 등록된 도름스 계정 |
| 마스터 | 모든 방송 관리. SSH 터널(서버 안으로 이어진 관리 통로)로 접속 |

방송은 전체 **최대 10개**, 도름스 회원은 한 사람당 1개까지 만들 수 있습니다. 마스터는 전체 10개 안에서 여러 개를 만들 수 있습니다. 방송은 모두 나가도 남으며 주인·운영진·마스터가 직접 삭제합니다. 방장이 나가도 다른 사람에게 자동으로 넘어가지 않습니다.

초대 주소는 `https://dolive.site/?room=방이름`입니다.

## 녹화와 분리 채팅

PC 방장은 화면공유와 TTS 사이의 **REC** 버튼에서 녹화를 설정합니다. 미리보기·화질·소리 포함 여부·저장 폴더를 고르고 시작합니다. 녹화 중에는 초록불과 진한 빨간 정지 표시가 보입니다.

공유 영상과 공유자의 구석 얼굴을 합쳐 **방장이 고른 PC 폴더**에 저장합니다. 채팅과 공유 화면 아래의 얼굴 줄은 포함하지 않습니다. 소리를 켜면 마이크·대화·공유 소리·TTS를 함께 담습니다. 서버로 녹화 파일을 보내지 않습니다. 최신 PC 크롬·엣지에서 사용하며, 가능한 브라우저에서는 MP4로 저장합니다. 다른 창에서 작업하는 동안에도 녹화하며, 공유 종료·교체·퇴장·방장 권한 해제 때 저장을 마무리합니다.

분리 채팅은 PC 방장이 화면공유 중 사용할 수 있습니다. 공유 화면·내 얼굴·채팅만 보기를 고르고, 그 아래에서 참여 인원과 프로필 사진을 확인합니다. 이 작은 창의 제목줄과 항상 앞에 뜨는 동작은 브라우저가 관리합니다.

## 서버 구조

```text
참여자 브라우저 → dolive.site
  TCP 443                → Caddy → 웹 화면 또는 통화 연결
  TCP 7881, UDP 50000~60000       → LiveKit 통화 서버

DigitalOcean 서버 안
  Next.js       웹 화면·채팅·도름스 로그인·글 읽기 (127.0.0.1:3000)
  LiveKit       목소리·카메라·공유 영상 주고받기 (127.0.0.1:7880)
  Caddy         HTTPS 연결과 인증서 관리
  systemd       세 프로그램 실행·자동 시작·복구 관리
```

기본 설치 위치는 `/opt/dolive`, 운영 설정은 `/etc/dolive/dolive.env`입니다. 다른 위치로 설치했다면 실제 위치를 확인하고 사용합니다. 운영은 Linux 프로그램을 직접 실행하는 방식이며 App Platform을 사용하지 않습니다.

Ubuntu 24.04 설치 방법, 서버 크기·비용·방화벽·도름스 연결·백업·복원은 [Linux 서버 안내](docs/linux/README.md)를 따릅니다. 프로그램 판과 내려받는 파일의 검사값은 [versions.env](server/linux/versions.env)에 고정되어 있습니다. 동시에 참여할 수 있는 인원은 실제 사용과 시험 결과로 판단하며, 아직 시험하지 않은 인원을 보장하지 않습니다.

## 관리자 접속

별도 관리자 웹 페이지는 없습니다. 운영진은 [dolive.site](https://dolive.site/)에 도름스 계정으로 로그인해 기존 입장 화면과 방 안 메뉴에서 관리합니다.

운영진 등록은 서버에서 다음 파일을 고칩니다. 한 줄에 도름스 닉네임 또는 아이디 한 명을 적습니다.

```sh
sudo -u dolive nano /opt/dolive/server/config/staff.txt
```

다시 켤 필요는 없지만 이미 방에 들어온 사람의 방 권한은 다음 입장부터 적용됩니다.

마스터는 관리자 컴퓨터에서 통로를 열고 `http://localhost:13000`으로 들어갑니다. 아래 계정과 서버 주소는 실제 접속 정보로 바꿉니다.

```text
ssh -N -L 127.0.0.1:13000:127.0.0.1:3000 -L 127.0.0.1:7880:127.0.0.1:7880 <계정>@<서버주소>
```

이것은 집 컴퓨터에서 서버를 켜는 명령이 아닙니다. 가상 서버에 연결하는 통로입니다. 끝나면 방에서 나온 뒤 `Ctrl+C`로 닫습니다. 자세한 설명은 [Linux 안내의 관리자 접속](docs/linux/README.md#9-마스터로-들어가기-ssh-터널)을 봅니다.

## 서버 운영과 새 코드 반영

아래 명령은 **가상 서버에 접속한 뒤** 실행합니다.

| 작업 | 명령 |
| :--- | :--- |
| 현재 응답 확인 | `sudo dolivectl health` |
| 설정·주소·인증서 점검 | `sudo dolivectl doctor` |
| 작동 기록 확인 | `sudo dolivectl logs` |
| 설정·방송 목록·인증서 백업 | `sudo dolivectl backup` |
| 새 코드 반영 | `sudo dolivectl update` |
| 서비스 시작·종료·재시작 | `sudo dolivectl start` / `stop` / `restart` |

새 코드를 반영하는 순서는 다음과 같습니다.

1. GitHub에 반영할 변경을 검사하고 올립니다. 운영 서버에 직접 수정한 코드가 있는지 확인하고 점검 시간을 정합니다.
2. Git으로 설치한 서버에서 `sudo dolivectl update`를 실행합니다. 백업 → 새 코드 받기 → 설치 부품과 웹 화면 만들기 → 다시 켜기를 처리합니다. 실패하면 이전 코드와 웹 화면으로 돌립니다.
3. `sudo dolivectl health`, `sudo dolivectl doctor`와 실제 사이트를 확인합니다. 로그인·대화·공유·카메라·채팅·글 읽기 및 변경한 기능을 확인합니다.

GitHub에 올리는 것만으로 운영 서버가 자동으로 바뀌지는 않습니다. 업데이트와 재시작은 연결을 끊고 메모리의 채팅을 지울 수 있으므로 방송 중에는 실행하지 않습니다. 서버에서 직접 고친 코드 때문에 업데이트가 멈추면 강제로 덮어쓰지 않습니다. Git으로 설치하지 않은 서버의 반영 방법은 [Linux 안내](docs/linux/README.md#13-새-버전으로-바꾸기)를 따릅니다.

## 남는 자료와 사라지는 자료

| 자료 | 보관 위치와 규칙 |
| :--- | :--- |
| 방송 목록·비밀번호·주인 | 서버의 `server/config/rooms.txt`, 직접 삭제할 때까지 유지 |
| 운영진 | 서버의 `server/config/staff.txt` |
| 채팅 글·사진 | 서버 메모리만 사용. 방이 비거나 웹 서버가 다시 시작되면 삭제 |
| 글 읽기로 만든 소리 | 파일로 보관하지 않음 |
| 녹화 영상 | 녹화한 방장의 PC에 저장, 서버에는 없음 |
| 내 사진과 일부 설정 | 참여자의 브라우저에 기억 |
| 서버 비밀 설정·인증서 | 서버의 비공개 설정과 백업에 보관 |

실제 비밀 키·방 비밀번호·운영진 목록·SSH 비밀 열쇠·백업은 GitHub에 올리지 않습니다. 코드만 내려받아서는 기존 운영 설정과 방송 목록이 복원되지 않습니다.

## 코드 작업

작업 전에 [AGENTS.md](AGENTS.md)를 읽습니다. 로컬 프로젝트는 코드 수정과 검사에 사용하고, 실제 서비스는 가상 서버에서 운영합니다.

```sh
npm --prefix apps/web ci
npm --prefix apps/web test
npm --prefix apps/web run build
```

새 작업 공간에서 웹을 만들려면 비공개 설정과 글 읽기 모델도 준비해야 합니다. 운영 서버의 비밀 설정을 공개 저장소에서 받거나 덮어쓰는 방식은 사용하지 않습니다. 현재 Next.js 안내는 `apps/web/node_modules/next/dist/docs/`에 있습니다.

루트 `.env.local`의 `DIGITALOCEAN_API_KEY`는 관리자 컴퓨터에서 공식 명령 도구 doctl로 서버를 관리할 때 사용하는 값입니다. 웹 앱이나 브라우저로 보내지 않습니다. doctl은 이 파일을 자동으로 읽지 않으며 실행할 때만 `DIGITALOCEAN_ACCESS_TOKEN`으로 전달합니다. API 키와 서버 접속용 SSH 열쇠는 서로 다릅니다.
