# DOLIVE 서버 설치와 운영 안내

DOLIVE는 동호회에서 목소리로 대화하고, 화면과 카메라를 공유하고, 채팅하는 웹사이트입니다. 참가자는 설치 없이 브라우저로 들어옵니다. 서버는 윈도우 컴퓨터 한 대에서 실행합니다.

**기존 서버를 다른 사람에게 넘긴다면, 깃허브에서 받는 것보다 기존 DOLIVE 폴더를 통째로 복사하는 방법을 권합니다.** 비밀 설정, 실행 프로그램, 글 읽기용 목소리 파일은 깃허브에 없습니다.

이 안내는 현재 윈도우 운영 방식을 기준으로 합니다. 별도 휴대폰 앱과 도커(프로그램을 묶어 실행하는 도구)는 사용하지 않습니다. 서버 대여료는 없지만 컴퓨터 전기료와 인터넷 비용은 듭니다.

## 1. 준비할 컴퓨터와 인터넷

| 항목 | 권장 조건 |
| :--- | :--- |
| 운영체제 | 윈도우 11, 인텔·AMD용 64비트 컴퓨터 |
| CPU(계산하는 부품) | 라이젠 5 5600G급 이상. 새로 마련하면 라이젠 5 7600급을 권장 |
| 메모리(작업 공간) | 16GB. 다른 작업도 함께 하면 32GB 고려 |
| 저장장치 | SSD(빠른 저장장치) 256GB 이상, 프로그램과 작업용 빈 공간 확보 |
| 그래픽 | 기본 내장 그래픽으로 서버 운영 가능 |
| 연결 | 공유기에 유선으로 연결 |
| 인터넷 | 보내는 속도 300Mbps를 설계 기준으로 삼음. 요금제 이름보다 실제 보내는 속도 확인 |
| 실행 환경 | Node.js 24 LTS(오래 지원하는 버전). 기존 운영 기록은 v24.15.0 |

N100 컴퓨터는 실제 운영 시험에서 글 읽기 때 CPU 점유율이 100%가 되어 통화까지 느려졌습니다. 글 읽기를 포함한 서버용으로 권하지 않습니다. 작은 컴퓨터는 냉각과 전력 제한에 따라 성능이 달라지므로 실제 통화 중 글 읽기를 시험하세요.

방송은 최대 4개이며 한 방 11~20명을 목표로 합니다. 4개 방을 모두 가득 채운 상황의 성능을 보장하는 수치는 아닙니다. 여러 방에서 글 읽기를 요청하면 현재는 차례로 처리합니다.

컴퓨터의 설정 → 시스템 → 전원에서 자동 절전을 **안 함**으로 설정하세요. 화면만 꺼지는 것은 괜찮지만 컴퓨터가 잠들면 서버도 멈춥니다. 재부팅 뒤에는 서버 켜기 창에서 다시 켜야 합니다.

## 2. 기존 서버를 다른 컴퓨터로 옮기기

이미 운영하던 DOLIVE를 이어받는 사람은 이 방법을 쓰세요.

1. 기존 운영자에게 DOLIVE 폴더 전체와 아래 파일을 받습니다. 파일은 개인 전달 수단으로 받고 깃허브에 올리지 않습니다.
2. 새 컴퓨터에 [Node.js 공식 설치 프로그램](https://nodejs.org/en/download)을 설치합니다. 24 LTS의 Windows x64 설치 파일을 선택합니다. 설치 후 새 PowerShell 창에서 `node -v`를 입력하여 `v24.`로 시작하는지 확인합니다.
3. 받은 폴더를 새 컴퓨터에 복사합니다. 예를 들어 `C:\DOLIVE`를 사용합니다. 아래 안내의 경로는 실제 폴더에 맞춰 바꿉니다.
4. 새 컴퓨터의 PowerShell에서 아래 명령으로 필요한 부품을 다시 설치합니다. 이 작업은 `node_modules`의 설치 부품을 다시 구성합니다.

   ```powershell
   Set-Location -LiteralPath 'C:\DOLIVE'
   npm.cmd --prefix apps/web ci
   ```

5. 같은 집에서 컴퓨터만 바꾸면 공유기의 고정 주소와 연결 대상을 새 컴퓨터로 바꿉니다. 다른 집으로 옮기면 새 집 공유기에서 다시 설정합니다. [4번](#4-공유기와-윈도우-방화벽-설정)을 따르세요.
6. 아래 설명대로 새 컴퓨터용 바로가기를 만듭니다. 받은 `DOLIVE.lnk`에는 옛 컴퓨터의 폴더 위치가 들어 있어 그대로 쓰면 안 됩니다.
7. **옛 컴퓨터에서 DOLIVE를 끈 뒤**, 새 컴퓨터에서 서버를 켭니다. 같은 DuckDNS 주소로 두 컴퓨터를 동시에 켜면 주소가 서로 바뀌어 접속이 불안정해질 수 있습니다.
8. [5번](#5-서버-켜기와-실제-접속-확인)의 실제 접속 확인을 끝냅니다. 새 서버가 정상인지 확인할 때까지 옛 폴더를 보관하되 옛 서버는 켜지 않습니다.

### 반드시 함께 받을 파일

| 위치 | 용도 |
| :--- | :--- |
| `server/config/livekit.yaml` | 통화 서버 설정과 비밀 키 |
| `server/config/duckdns.env` | 바깥 주소 이름과 주소를 바꿀 수 있는 비밀 토큰 |
| `server/config/staff.txt` | 운영진 목록. 운영진이 없으면 없어도 됨 |
| `server/config/rooms.txt` | 방송 목록, 비밀번호, 방 주인. 기존 방송을 유지하려면 필요 |
| `apps/web/.env.local` | 통화 서버 키와 도름스 연결 설정 |
| `server/bin/livekit-server.exe` | 통화 서버 실행 프로그램 |
| `server/bin/caddy.exe` | 바깥 접속과 암호화 연결을 맡는 프로그램 |
| `server/bin/lk.exe` | 통화 서버 확인용 명령 도구. 일반 켜기에는 필수 아님 |
| `apps/web/models/supertonic/` | 글 읽기용 파일 전부, 약 400MB |

실행 파일과 목소리 파일까지 받은 경우 [3번](#3-깃허브에서-처음-설치하기)에서 다시 받을 필요는 없습니다. 기존 주소와 도름스 연결을 유지하면 기존 설정을 그대로 사용합니다. **주소를 바꾸면 DuckDNS 설정뿐 아니라 도름스에 등록한 주소와 `.env.local`도 함께 맞춰야 합니다.**

### 새 컴퓨터용 바로가기 만들기

PowerShell에 아래 내용을 넣습니다. 첫 줄의 폴더만 실제 위치로 바꾸세요. 이 명령은 그 폴더의 `DOLIVE.lnk`를 새로 만듭니다.

```powershell
$dolivePath = 'C:\DOLIVE'
$shortcut = (New-Object -ComObject WScript.Shell).CreateShortcut("$dolivePath\DOLIVE.lnk")
$shortcut.TargetPath = 'C:\Windows\System32\conhost.exe'
$shortcut.Arguments = "--headless powershell.exe -NoProfile -ExecutionPolicy Bypass -File `"$dolivePath\scripts\dolive_panel.ps1`""
$shortcut.WorkingDirectory = $dolivePath
$shortcut.IconLocation = "$dolivePath\scripts\icons\dolive.ico,0"
$shortcut.Save()
```

이후 `DOLIVE.lnk`를 두 번 누르면 켜기·끄기 창이 열립니다. 바로가기는 컴퓨터마다 다르므로 깃허브에 올리거나 다른 컴퓨터 것으로 덮어쓰지 않습니다.

## 3. 깃허브에서 처음 설치하기

기존 폴더를 받을 수 없거나 별도 서버를 새로 만드는 경우입니다. 기존 서버 인계라면 먼저 운영자에게 빠진 파일을 요청하세요. 아래 절차로 새 설정을 만들면 기존 방송 목록과 주인 정보가 저절로 복원되지는 않습니다.

### 3-1. 코드와 설치 부품 받기

1. [DOLIVE 깃허브](https://github.com/cordmin/DOLIVE)에서 `Code` → `Download ZIP`을 눌러 압축 파일을 받습니다.
2. 압축을 풀고 폴더를 `C:\DOLIVE` 같은 위치에 둡니다. 그 안에 `apps`, `scripts`, `server`가 있어야 합니다.
3. [Node.js](https://nodejs.org/en/download) 24 LTS의 Windows x64 설치 프로그램을 설치합니다.
4. 새 PowerShell 창에서 다음 명령을 실행합니다.

   ```powershell
   Set-Location -LiteralPath 'C:\DOLIVE'
   node -v
   npm.cmd --prefix apps/web ci
   ```

Git(코드 변경 내용을 받는 도구)을 이미 쓸 수 있다면 ZIP 대신 `git clone https://github.com/cordmin/DOLIVE.git C:\DOLIVE`로 받아도 됩니다. ZIP으로 받은 폴더에서는 이후 `git pull`을 사용할 수 없습니다.

### 3-2. 통화와 바깥 접속 프로그램 받기

현재 정상 작동하는 서버의 실행 파일을 받는 방법이 가장 확실합니다. 처음 받는 경우에는 아래 공식 공개 저장소를 사용합니다. 새 버전의 프로그램은 접속·통화 시험을 마친 뒤 운영에 사용하세요.

| 프로그램 | 공식 받는 곳 | 받을 파일과 최종 위치 |
| :--- | :--- | :--- |
| LiveKit(통화 서버) | [공식 배포 목록](https://github.com/livekit/livekit/releases) | Windows amd64용 압축 파일을 풀고 `server/bin/livekit-server.exe`에 놓기 |
| Caddy(암호화 접속 담당) | [공식 배포 목록](https://github.com/caddyserver/caddy/releases) | Windows amd64용 압축 파일을 풀고 `server/bin/caddy.exe`에 놓기 |
| lk(확인용 도구, 선택 사항) | [공식 배포 목록](https://github.com/livekit/livekit-cli/releases) | Windows amd64용 파일을 풀고 실행 파일을 `server/bin/lk.exe`로 놓기 |

배포 페이지의 `Assets`는 받는 파일 목록입니다. `amd64`는 일반 인텔·AMD 64비트 컴퓨터용이라는 뜻입니다. Linux용, ARM용, `Source code`(프로그램 원본만 있는 파일)는 고르지 않습니다. `server/bin` 폴더가 없으면 만듭니다.

### 3-3. 통화 서버 키 만들기

1. `server/config/livekit.example.yaml`을 복사하여 같은 폴더에 `livekit.yaml`이라는 이름으로 둡니다. 메모장 저장 시 `livekit.yaml.txt`가 되지 않도록 확장자를 확인합니다.
2. 다음 명령으로 임의의 긴 비밀값을 하나 만듭니다. 나온 값은 비공개로 보관합니다.

   ```powershell
   node -e "console.log(require('node:crypto').randomBytes(32).toString('hex'))"
   ```

3. `livekit.yaml`의 `PUT_A_RANDOM_48_CHAR_SECRET_HERE` 부분을 방금 만든 값으로 바꿉니다. `keys` 아래의 `dolive`라는 키 이름은 그대로 둡니다.
4. 예시의 나머지 설정도 유지합니다. 특히 `webhook`(퇴장 사실을 웹 화면에 알려 주는 설정)이 있어야 빈 방의 채팅이 지워집니다.

설정의 중요한 부분은 다음과 같습니다. **아래 비밀값 설명 문구를 그대로 실제 키로 사용하지 마세요.**

```yaml
keys:
  dolive: 여기에_새로_만든_비밀값
webhook:
  api_key: dolive
  urls:
    - http://127.0.0.1:3000/api/livekit
```

### 3-4. 바깥 주소와 도름스 연결 준비

1. [DuckDNS](https://www.duckdns.org)에 로그인해서 사용할 주소를 만듭니다. 예를 들어 이름이 `mydolive`이면 전체 주소는 `https://mydolive.duckdns.org`입니다. 기존 DOLIVE를 인계받는다면 기존 주소의 관리 권한을 먼저 넘겨받습니다.
2. `server/config/duckdns.example.env`를 복사하여 `duckdns.env`로 만듭니다.
3. `DUCKDNS_DOMAIN`에는 `.duckdns.org`를 뺀 이름만 넣고, `DUCKDNS_TOKEN`에는 DuckDNS에서 받은 토큰을 넣습니다. 값 주변에 따옴표를 붙이지 않습니다.

   ```text
   DUCKDNS_DOMAIN=mydolive
   DUCKDNS_TOKEN=여기에_개인_토큰
   ```

4. [도름스 연결 관리](https://dorms.school/connect)에서 사이트를 등록하거나 기존 DOLIVE 연결의 관리 권한을 넘겨받습니다. 기존 사이트를 이어받는 경우 새 사이트를 임의로 중복 등록하지 말고 기존 운영자와 확인합니다.
5. 사이트 주소는 DuckDNS의 전체 HTTPS 주소로 맞춥니다. 로그인 후 돌아오는 주소는 `https://mydolive.duckdns.org/api/auth/dorms/callback`입니다. 도름네이션을 쓰는 경우 돌아오는 주소는 `https://mydolive.duckdns.org/api/auth/dorms/donation/callback`이며, 도름스에서 별도 신청·승인이 필요한지 확인합니다.
6. 도름스가 발급한 사이트 식별값을 아래 `DORMS_CLIENT_ID`에 넣습니다. 도름스 등록·승인이 끝나기 전에는 일반 회원의 로그인이나 도름네이션이 작동하지 않을 수 있습니다.

`apps/web/.env.local`을 만들고 아래 네 값을 넣습니다. 파일 이름이 `.env.local.txt`가 되지 않게 확인하세요.

```text
LIVEKIT_API_KEY=dolive
LIVEKIT_API_SECRET=livekit.yaml에_넣은_것과_같은_비밀값
DORMS_CLIENT_ID=도름스에서_받은_사이트_식별값
DORMS_SITE_URL=https://mydolive.duckdns.org
```

`LIVEKIT_API_KEY`는 `livekit.yaml`의 키 이름과 같아야 하고, `LIVEKIT_API_SECRET`도 그 키의 비밀값과 같아야 합니다. `DORMS_SITE_URL`에는 방 주소나 `/api`를 붙이지 않습니다. 예시 이름 `mydolive`는 본인의 이름으로 바꾸세요.

`LIVEKIT_PUBLIC_URL`(친구들이 접속할 통화 주소)은 정상 시작 명령이 DuckDNS 이름으로 자동 설정합니다. 일반 설치에서는 따로 적을 필요가 없습니다.

### 3-5. 글 읽기용 목소리 파일 받기

글 읽기는 Supertonic 3(컴퓨터 안에서 목소리를 만드는 프로그램)를 사용합니다. 기존 서버의 `apps/web/models/supertonic` 폴더를 통째로 받았다면 이 단계는 건너뜁니다.

1. [DOLIVE가 사용하는 모델 저장소](https://huggingface.co/supertone-oss-archive/supertonic-3/tree/main)를 엽니다. 받는 곳이 변경되었다면 기존 운영자에게 정상 작동하는 파일을 요청하세요.
2. 그곳의 `onnx` 폴더 안 파일을 모두 받아 `apps/web/models/supertonic`에 직접 넣습니다. `supertonic/onnx` 안에 한 번 더 넣지 않습니다. 별도 데이터 파일이 있으면 그것도 함께 받습니다.
3. `voice_styles` 폴더의 `F1.json`, `F2.json`, `M1.json`도 같은 `supertonic` 폴더에 직접 넣습니다.
4. 최소한 아래 파일들이 있는지 확인합니다. 작은 설명 문서나 다운로드 주소만 담긴 파일이 아니라 실제 모델 파일을 받아야 합니다.

```text
apps/web/models/supertonic/
  duration_predictor.onnx
  text_encoder.onnx
  vector_estimator.onnx
  vocoder.onnx
  tts.json
  unicode_indexer.json
  F1.json
  F2.json
  M1.json
```

서연은 F2, 하은은 F1, 민준과 마왕은 M1을 사용합니다. 마왕은 민준의 높낮이와 말 빠르기를 바꿔 만듭니다. 네 목소리를 유지하려면 세 JSON 파일이 모두 있어야 합니다. 모델·그림 등 외부 자료의 사용 조건은 각 원본의 안내를 따릅니다.

이제 [2번의 바로가기 만들기](#새-컴퓨터용-바로가기-만들기)와 아래 연결 설정을 진행하세요.

## 4. 공유기와 윈도우 방화벽 설정

### 4-1. 서버 컴퓨터의 내부 주소 고정

1. 새 서버를 공유기에 유선으로 연결합니다.
2. PowerShell에서 `ipconfig`를 입력하여 유선 연결의 `IPv4 주소`와 `기본 게이트웨이`를 확인합니다. IPv4 주소는 집 안에서 쓰는 컴퓨터 주소이고, 기본 게이트웨이는 보통 공유기 관리 주소입니다.
3. 브라우저로 공유기 관리 화면을 열어 로그인합니다.
4. 공유기의 DHCP(집 안 주소를 나누는 기능) 설정에서 서버 컴퓨터에 같은 주소를 계속 주도록 지정합니다. 보통 MAC 주소(컴퓨터 연결 장치의 고유 번호)로 예약하는 기능입니다.
5. 컴퓨터를 다시 연결하거나 재부팅하여 정한 주소를 받았는지 `ipconfig`로 확인합니다.

공유기에서 주소를 예약하는 방법을 권합니다. 윈도우에 아무 주소나 직접 넣으면 다른 기기와 겹칠 수 있습니다. 옛 컴퓨터에 예약된 주소를 새 컴퓨터로 옮길 경우 예약 대상도 새 컴퓨터의 연결 장치로 바꿉니다.

### 4-2. 포트포워딩 설정

포트포워딩은 **밖에서 들어온 통신을 서버 컴퓨터로 보내는 길**입니다. 다음 세 길의 대상은 모두 새 서버의 고정 내부 주소로 맞춥니다.

| 종류 | 바깥 번호 | 서버 쪽 번호 | 용도 |
| :--- | :--- | :--- | :--- |
| TCP | 443 | 443 | 웹 접속과 통화 연결 준비 |
| TCP | 7881 | 7881 | 통화 연결 |
| UDP | 50000~60000 | 50000~60000 | 실제 목소리·카메라·공유 화면 |

TCP와 UDP는 통신 방식의 이름입니다. 공유기에서 표에 적힌 방식을 그대로 고르세요. 내부 프로그램용 3000·7880번은 외부에 열 필요가 없습니다. 모든 길을 한꺼번에 여는 DMZ는 사용하지 않습니다.

기존 SK브로드밴드 GNT245에서는 [서비스] → [방화벽] → [포트 포워딩]에 있습니다. DHCP 예약은 [서비스] → [DHCP] → [MAC 기반 할당]에 있습니다. 이 공유기는 연결 줄을 직접 고치지 못하므로 **DOLIVE에 해당하는 줄만 선택해 삭제한 뒤 다시 추가**합니다. [모두 삭제]를 누르면 다른 설정까지 없어집니다. 다른 공유기는 메뉴 이름이 다를 수 있습니다.

현재 Caddy 설정은 **443번으로만 인증서(암호화 접속 증명)를 받습니다.** 기존 공유기는 바깥 80번을 막으므로 인증서 설정의 `disable_http_challenge`를 지우거나 80번 방식으로 바꾸지 않습니다.

새 집에서 바깥 접속이 안 되면 공유기가 한 대 더 앞에 있는지, 통신사가 공인 주소를 제공하는지 확인해야 할 수 있습니다. 이 경우 새 공유기 설정만으로 해결되지 않을 수 있습니다.

### 4-3. 윈도우 방화벽 허용

새 서버에서 시작 메뉴의 PowerShell을 오른쪽 클릭하여 **관리자 권한으로 실행**합니다. 아래 명령은 처음 한 번 실행합니다. 이미 같은 규칙이 있으면 중복으로 만들 필요는 없습니다.

```powershell
New-NetFirewallRule -DisplayName 'DOLIVE 443' -Direction Inbound -Protocol TCP -LocalPort 443 -Action Allow -Profile Any
New-NetFirewallRule -DisplayName 'DOLIVE LiveKit TCP' -Direction Inbound -Protocol TCP -LocalPort 7881 -Action Allow -Profile Any
New-NetFirewallRule -DisplayName 'DOLIVE LiveKit UDP' -Direction Inbound -Protocol UDP -LocalPort 50000-60000 -Action Allow -Profile Any
```

`-Profile Any`는 윈도우가 인터넷 연결을 공용으로 판단해도 허용하라는 뜻입니다. 처음 프로그램을 켤 때 윈도우 허용 창이 뜨면 공용 연결을 포함해 허용합니다. 방화벽 전체를 끄지는 않습니다.

## 5. 서버 켜기와 실제 접속 확인

1. 옛 서버가 꺼져 있는지 확인합니다.
2. 새 컴퓨터에서 `DOLIVE.lnk`를 열고 켜기를 누릅니다. 처음에는 웹 화면을 만드는 시간이 필요합니다.
3. 통화 서버·웹 화면·바깥 연결 세 항목이 모두 정상인지 확인합니다. 이것만으로 휴대폰의 실제 통화까지 확인된 것은 아닙니다.
4. 서버 컴퓨터의 브라우저에서 `http://localhost`를 엽니다. 여기서는 로그인 없이 마스터(모든 방을 관리하는 사람)로 들어옵니다.
5. 휴대폰에서 **와이파이를 끄고 모바일 데이터로** 본인의 `https://이름.duckdns.org` 주소를 엽니다. 같은 집 와이파이로만 시험하면 바깥에서 들어오는 길을 확인할 수 없습니다.
6. 도름스 로그인 후 같은 방에 들어가 양쪽 목소리가 들리는지 확인합니다. 이어 화면공유, 카메라, 채팅 글·사진을 확인합니다.
7. 채팅에 `/안녕하세요`를 보내서 글 읽기가 나오는지 확인합니다. TTS(글 읽기) 설정에서 네 목소리의 미리 듣기도 확인합니다.
8. 시험을 마치면 서버 컴퓨터의 확인용 브라우저를 **입장 화면 `/`로 돌아오게** 합니다. 방에 남아 있으면 다른 사람의 목소리가 서버 스피커로 나와 되울릴 수 있습니다.

처음 HTTPS 주소를 쓰면 Caddy가 인증서를 새로 받습니다. 주소가 새 인터넷을 가리키고 443번 길이 열려 있어야 성공합니다. 실패하면 `server/logs/caddy.err.log`를 확인합니다.

## 6. 매일 켜고 끄기

평소에는 `DOLIVE.lnk`를 열어 켜기·끄기를 누르면 됩니다. 끄기를 누르면 먼저 방 안 사람들에게 방송 종료를 알리고 프로그램을 종료합니다. 컴퓨터 전원을 바로 끄기보다 서버의 끄기 버튼을 먼저 쓰세요.

명령으로 실행하려면 PowerShell에서 DOLIVE 폴더로 이동한 뒤 사용합니다.

```powershell
Set-Location -LiteralPath 'C:\DOLIVE'
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\start_dolive.ps1
```

끄기:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\start_dolive.ps1 -Stop
```

웹 화면을 반드시 다시 만들어 켜기:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\start_dolive.ps1 -Build
```

이 컴퓨터에서만 확인하기:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\start_dolive.ps1 -Local
```

`-Local`은 DuckDNS 갱신과 Caddy를 생략합니다. 이때 입장 주소는 **`http://localhost:3000`**입니다. 외부 접속과 도름스 로그인의 정상 여부를 확인하는 방법은 아닙니다.

시작 명령도 먼저 기존 프로그램을 끄므로, 실행 중 다시 켜기를 누르면 사람들이 연결에서 나갈 수 있습니다. 현재 종료 명령은 이 컴퓨터의 LiveKit·Caddy와 `next start`로 실행한 웹 프로그램을 종료합니다. 같은 컴퓨터에서 다른 사이트를 함께 운영할 때는 주의하세요.

## 7. 운영진과 방송 관리

### 관리하는 사람의 차이

| 구분 | 누구인가 | 할 수 있는 일 |
| :--- | :--- | :--- |
| 마스터 | 서버 컴퓨터에서 `http://localhost`로 접속한 사람 | 모든 방송 관리, 전체 최대 4개 안에서 여러 방송 만들기 |
| 운영진 | `staff.txt`에 적힌 도름스 닉네임의 회원 | 모든 방송 관리. 한 사람당 방송 만들기는 1개 |
| 방 주인 | 방송을 만든 도름스 회원 | 자신이 만든 방송 관리, 방 안 회원에게 방장 넘기기 |
| 일반 회원 | 도름스로 로그인한 참여자 | 방송 1개 만들기, 허용된 방송에 참여 |
| 비회원 | 비회원도 허용한 방송의 참여자 | 방송 참여. 방송 만들기는 못 함 |

서버 컴퓨터를 직접 쓰는 사람은 마스터 권한을 가질 수 있으므로 컴퓨터의 로그인 계정도 함께 관리하세요. 같은 집의 다른 컴퓨터에서 접속하는 것만으로 마스터가 되지는 않습니다.

### 운영진 추가·삭제

서버 켜기 창의 톱니바퀴를 눌러 DOLIVE 설정에서 운영진 목록을 고칩니다. 파일로는 `server/config/staff.txt`에 도름스 닉네임을 한 줄에 한 명씩 적습니다. 직접 편집한다면 UTF-8로 저장하세요. 닉네임은 도름스에 표시된 것을 사용합니다.

설정은 요청마다 다시 읽습니다. 방 안의 운영진 권한은 다음 입장부터 적용되므로 바뀐 사람은 방에서 나갔다 들어오게 합니다.

### 방송 만들기·고치기·삭제

1. 입장 화면의 방송 목록에서 [+ 방 만들기]를 누릅니다.
2. 방 이름, 비밀번호, 들어올 사람을 고르고 만들기를 누릅니다. 비밀번호는 비워도 됩니다.
3. 만들기는 목록에 추가하는 동작입니다. 실제로 들어가려면 그 방을 고른 뒤 [LIVE 입장]을 누릅니다.
4. 내가 관리할 수 있는 방송의 톱니바퀴에서 이름·비밀번호·입장 조건을 고칩니다.
5. 삭제는 방 설정의 삭제 버튼을 눌러 확인합니다. 이름을 바꾸거나 지우면 방 안 사람들은 바로 나가집니다.

최대 4개 제한은 마스터의 방송까지 합친 전체 개수입니다. 방송은 모두 나가거나 서버를 꺼도 남습니다. 필요 없는 방송은 주인·운영진·마스터가 직접 삭제합니다. 초대 주소는 `https://이름.duckdns.org/?room=방이름`이며, 해당 방송이 선택된 입장 화면을 엽니다.

방 안에서 참여자를 오른쪽 클릭하면 방장 메뉴가 나옵니다. 휴대폰에서는 꾹 누릅니다. 화면공유 허락, 마이크·카메라 끄기, 강퇴 등을 할 수 있습니다. 방 주인은 방 안 도름스 회원에게 방장 넘기기를 할 수 있습니다. 강퇴는 다시 입장하는 것까지 막지는 않습니다.

방송 목록은 `server/config/rooms.txt`에 저장됩니다. 한 줄의 항목은 **방 이름, 비밀번호, `guest` 또는 `members`, 만든 회원의 id(고유 번호)**이며 사이를 탭으로 나눕니다. `guest`는 비회원도, `members`는 도름스 회원만입니다. 직접 수정하기보다 입장 화면을 쓰세요. 파일이 없으면 비밀번호 없는 기본 DOLIVE 방송 하나를 사용합니다.

### 글 읽기와 카메라

글 읽기는 각 참여자의 TTS 버튼에서 끄기·항상·`/입력`과 목소리를 고릅니다. 처음 값은 `/입력`과 서연입니다. 선택은 각 사람 브라우저에 기억합니다. 보낸 사람도 듣고, 말풍선 앞 스피커를 누르면 서버가 다시 읽습니다.

카메라는 누구나 켤 수 있습니다. 일반 참여자의 화면공유는 방장이 허락해야 합니다. 화면공유가 없으면 켜진 카메라를 바둑판처럼 보여 주고, 공유 중에는 공유자의 얼굴을 구석이나 아래 줄에 보여 줍니다. PC의 배경 흐리기는 보내는 사람의 브라우저에서 처리합니다.

## 8. 보관할 것과 사라지는 것

| 내용 | 어디에 남는가 | 언제 사라지는가 |
| :--- | :--- | :--- |
| 방송 목록·비밀번호·방 주인 | `server/config/rooms.txt` | 직접 삭제할 때 |
| 운영진 목록 | `server/config/staff.txt` | 직접 수정할 때 |
| 채팅 글·사진 | 서버의 임시 기억 공간 | 그 방에 모두 나가거나 웹 서버가 다시 시작될 때 |
| 글 읽기로 만든 소리 | 보내는 동안만 사용, 저장하지 않음 | 보낸 뒤 남겨 두지 않음 |
| 직접 고른 내 프로필 사진 | 각 사람 브라우저에 보관, 입장 중 서버 임시 기억 공간에도 올림 | 브라우저 자료를 지우면 내 사진 선택이 사라질 수 있음 |
| 마이크 선택 | 방에 있는 동안 기억 | 나갈 때 |
| 글 읽기·카메라의 일부 설정 | 각 사람 브라우저 | 브라우저 자료를 지우면 초기화될 수 있음 |

글 읽기용 모델 파일과 방 목록·설정 파일은 보관하지만 **채팅 기록·채팅 사진·읽은 소리를 파일로 저장하지 않습니다.** 읽어 주는 ‘음성’ 참여자는 방에 남은 사람 수에 넣지 않습니다.

백업(따로 보관하는 복사본)은 서버를 끈 뒤 DOLIVE 폴더 전체를 개인 보관 장소에 복사하는 방법이 간단합니다. 비밀 설정과 방송 비밀번호가 있으므로 공개 공유 링크나 깃허브에 올리지 않습니다. `node_modules`와 `.next`는 다시 설치·생성할 수 있지만 실행 파일·설정·모델은 반드시 챙깁니다.

## 9. 새 버전으로 바꾸기

1. 사람들에게 종료를 알리고 서버를 끕니다.
2. 현재 폴더를 따로 복사해 둡니다. 특히 비밀 설정, 방송 목록, 목소리 파일을 지킵니다.
3. Git으로 받은 폴더라면 아래 명령으로 변경 내용을 확인하고 새 코드를 받습니다.

   ```powershell
   Set-Location -LiteralPath 'C:\DOLIVE'
   git status --short
   git pull --ff-only origin main
   npm.cmd --prefix apps/web ci
   ```

4. 변경 내용이 겹쳐 명령이 실패하면 강제로 덮어쓰지 말고 기존 운영자나 유지보수 담당자와 확인합니다. `DOLIVE.lnk`는 새 컴퓨터에서 만든 것을 유지합니다.
5. ZIP으로 설치했다면 새 ZIP을 별도 폴더에 풀고, 기존 비밀 설정·실행 파일·모델·방송 목록을 넘긴 뒤 같은 설치 절차로 준비합니다. 기존 서버 폴더는 확인이 끝날 때까지 보관합니다.
6. `-Build`로 켜서 새 웹 화면을 만듭니다. 이 명령은 실행 중인 서버를 다시 시작합니다.
7. [5번](#5-서버-켜기와-실제-접속-확인)의 바깥 접속·통화·글 읽기를 확인합니다.

보통 화면 코드가 바뀌면 켤 때 자동으로 다시 만듭니다. 하지만 주소나 `.env.local` 같은 설정을 바꾼 경우에는 자동 판단에만 맡기지 말고 `-Build`로 다시 만드세요. 실행 파일을 새 버전으로 바꾸는 일은 Git으로 코드만 받는 것과 별개입니다.

## 10. 문제가 생겼을 때

먼저 `server/logs` 폴더를 봅니다. `web.err.log`는 웹 화면, `livekit.err.log`는 통화 서버, `caddy.err.log`는 바깥 접속의 오류 기록입니다. 같은 이름의 `.out.log`에도 단서가 있을 수 있습니다. `build.log`는 웹 화면을 만드는 기록입니다.

기록이나 화면을 다른 사람에게 보낼 때는 비밀 키·토큰·개인정보가 있는지 먼저 확인합니다.

| 증상 | 확인 순서 |
| :--- | :--- |
| 웹 화면 만들기 실패 | `build.log` 확인 → Node.js 24 확인 → `npm.cmd --prefix apps/web ci` → `-Build`로 다시 켜기 |
| localhost부터 안 열림 | 세 프로그램 상태 확인 → `web.err.log`, `caddy.err.log` 확인 → 필요한 파일과 사용 중인 번호 확인 |
| localhost는 되는데 바깥 접속 실패 | 새 서버의 내부 주소 → 공유기의 세 연결 길 → 윈도우 방화벽 → DuckDNS 설정과 주소 갱신 기록 확인 |
| 인증서 오류 | 주소가 현재 인터넷을 가리키는지 → 바깥 443번 연결 → `caddy.err.log` 확인. 80번 방식으로 바꾸지 않기 |
| 입장은 되지만 소리·영상이 안 옴 | TCP 7881과 UDP 50000~60000의 공유기·방화벽 설정 → `livekit.yaml`의 `use_external_ip: true` 확인 |
| 입장권 오류 | `.env.local`의 통화 키 이름·비밀값이 `livekit.yaml`과 같은지 확인 |
| 도름스 로그인 실패 | 도름스 사이트 등록·허용 상태 → 사이트 식별값 → 등록한 HTTPS 주소·돌아오는 주소 → `.env.local` 확인 |
| 글 읽기 실패 | `web.err.log` → 모델 파일 위치·크기 → F1·F2·M1 파일 → CPU 부하 확인 |
| 빈 방 채팅이 안 지워짐 | `livekit.yaml`에 `webhook`과 맞는 `api_key`가 있는지, `/api/livekit`으로 알리는지 확인 |
| 도름네이션만 실패 | 도름스 신청·승인 상태와 회원의 연결 허용 확인. 결과가 불명확한 보내기는 새로 보내지 말고 원래 결과부터 확인 |

개발·유지보수 담당자가 쓸 확인 명령도 있습니다. 일반 운영자가 매번 실행할 필요는 없습니다.

```powershell
Set-Location -LiteralPath 'C:\DOLIVE\apps\web'
npm.cmd test
node tests/room-lifecycle.cjs
```

첫 명령은 코드 시험입니다. 두 번째는 서버가 켜진 상태에서 빈 방 채팅 정리를 확인합니다. 실제 도름스 로그인과 휴대폰 통화는 자동 시험만으로 확인되지 않습니다. 도름네이션 관련 확인 기록과 남은 실제 시험은 [별도 안내](docs/donation/README.md)를 봅니다.

## 11. 새 운영자에게 넘기는 확인표

- [ ] DOLIVE 폴더 전체와 비공개 설정·실행 프로그램·목소리 파일을 받았다.
- [ ] DuckDNS의 기존 주소를 계속 관리할 수 있다. 주소 변경 토큰뿐 아니라 계정 관리·복구 방법도 기존 운영자와 정했다.
- [ ] 도름스에 등록한 DOLIVE 연결과 도름네이션의 관리 주체를 기존 운영자와 정했다. 공개 문서에 계정 비밀번호를 적지 않았다.
- [ ] 새 서버의 Node.js 24, 설치 부품, 새 바로가기를 준비했다.
- [ ] 새 컴퓨터의 내부 주소를 고정하고 공유기의 세 길을 맞췄다.
- [ ] 새 컴퓨터의 윈도우 방화벽을 허용하고 자동 절전을 껐다.
- [ ] 옛 서버를 끈 뒤 새 서버만 켰다.
- [ ] 모바일 데이터로 바깥 접속·로그인·양방향 통화·화면공유·카메라·채팅·글 읽기를 확인했다.
- [ ] 기존 방송 목록과 방 주인, 운영진 목록이 유지되어 있다.
- [ ] 켜기·끄기, 방송 삭제, 기록 확인, 폴더 복사를 새 운영자가 직접 해 봤다.
- [ ] 확인용 브라우저는 방에서 나와 입장 화면으로 돌아왔다.

### 파일 위치와 작동 구조

```text
참가자 브라우저
  ├─ TCP 443 → 공유기 → Caddy → 웹 화면 또는 통화 연결
  └─ TCP 7881, UDP 50000~60000 → 공유기 → LiveKit 통화 서버

서버 컴퓨터 안
  Caddy: 바깥 암호화 접속 담당
  Next.js: 127.0.0.1:3000에서 웹 화면·채팅·로그인·글 읽기 실행
  LiveKit: 127.0.0.1:7880에서 통화 관리
```

| 위치 | 내용 |
| :--- | :--- |
| `scripts/dolive_panel.ps1` | 켜기·끄기 창과 운영진 설정 |
| `scripts/start_dolive.ps1` | 실제 시작·종료·웹 다시 만들기 |
| `apps/web` | 웹사이트 코드와 설치 부품 |
| `server/config` | 통화·주소·운영진·방송 설정 |
| `server/bin` | 내려받은 실행 프로그램 |
| `server/logs` | 작동 기록과 오류 기록 |
| `apps/web/models/supertonic` | 글 읽기용 모델과 목소리 파일 |
| [정리 기록](docs/정리_기록.md) | 유지보수 조사·변경·확인 기록 |

공개 깃허브에는 실제 비밀 키, DuckDNS 토큰, 운영진 목록, 방송 비밀번호, 내려받은 실행 프로그램과 모델을 올리지 않습니다.
